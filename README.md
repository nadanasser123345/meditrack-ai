# 🩺 MediTrack AI - Cardiology Edition
> **نظام السجل الطبي القلبي الذكي المعزز بالذكاء الاصطناعي**

---

## 📌 1. نبذة عن المشروع (Overview)
**MediTrack AI** هو تطبيق ويب طبي ذكي متخصص في **أمراض القلب والأوعية الدموية (Cardiology)**. 
يهدف النظام إلى حل معضلة ضياع التاريخ المرضي لمرضى القلب، وصعوبة قراءة السجلات الطبية الطويلة في العيادات، وحماية المرضى من **التعارضات الدوائية القاتلة (Drug-Drug Interactions)** بين أدوية السيولة والمسكنات، مع تنظيم التعليمات الطبية للمريض بلغة مفهومة.

---

## 💡 2. المشكلة والحل (Problem & Solution)
* **المشكلة:**
  1. مريض القلب يحمل تاريخاً طويلاً (دعامات، قسطرة، أدوية سيولة وضغط، تحاليل، وحساسية).
  2. وقت الكشف (10 دقائق) لا يكفي الطبيب لقراءة سجلات سنوات مضت.
  3. خطورة التعارض الدوائي (كتابة مسكن عادي مثل كتافلام لمريض دعامات وسيولة يسبب نزيفاً معوياً حاداً).
  4. نسيان المريض لمواعيد الجرعات والتعليمات المعقدة.
* **الحل:**
  1. مشاركة السجل الطبي عبر **QR Code مؤقت (15 دقيقة)** لضمان الخصوصية.
  2. **تلخيص سريري فوري بالـ AI (AI Clinical Summarization)** لأهم المؤشرات والتحذيرات.
  3. **فاحص التعارض الدوائي الذكي (AI Drug Safety Guardrails)** للتحقق من أمان أي دواء جديد قبل صرفه.
  4. **إعادة تنظيم تعليمات الطبيب** في جدول مواعيد يومي وإرشادات طوارئ بلغة المريض.

---

## 📊 3. مصدر البيانات (Dataset Benchmark)
* استند المشروع إلى بيانات معيارية معتمدة من منصة **Kaggle** العالمية:
  - **ملف الداتا:** `data/kaggle_heart_disease_benchmark.csv`
  - **مصدر الداتا:** *Kaggle UCI Heart Disease Dataset & Clinical Records*
  - **الحالات المسجلة:** 10 حالات قلبية سريرية متكاملة (`data/cardiology_patients.json`).

## 👥 4. توزيع الأدوار على الفريق (7 أفراد)

| # | العضو | الدور التخصصي | المهام المسندة إليه |
|:---:|:---|:---|:---|
| **1** | العضو الأول | **Backend & Architecture** | هيكلة السيرفر بـ Flask وإدارة الـ Endpoints ومستودع GitHub. |
| **2** | العضو الثاني | **Doctor Frontend** | تصميم شاشة الطبيب وماسح الـ QR وعرض ملخص الـ AI السريري. |
| **3** | العضو الثالث | **Patient Frontend** | تصميم شاشة المريض واستمارة السجل القلبي وتوليد كود الـ QR. |
| **4** | العضو الرابع | **Database & Security** | بناء جداول الداتابيز بـ SQLAlchemy ونظام تشفير وصلاحية الـ QR (15 دقيقة). |
| **5** | العضو الخامس | **AI Clinical Summarizer** | هندسة برومبت التلخيص الطبي القلبي وصيغة Structured JSON ومنع الهلوسة. |
| **6** | العضو السادس | **AI Drug Safety Engine** | موديول كشف التعارضات الدوائية لمرضى القلب وإعادة صياغة تعليمات المريض. |
| **7** | العضو السابع | **Data & QA Lead** | إدارة داتا Kaggle والحالات الـ 10، واختبارات النظام وسيناريو العرض التقديمي. |

## 🗂️ 5. الهيكل البرمجي للمشروع (Folder Structure)

```text
Project AI/
├── app/
│   ├── __init__.py           # تهيئة تطبيق Flask وقاعدة البيانات
│   ├── models.py             # نماذج قاعدة البيانات (SQLAlchemy)
│   ├── routes.py             # مسارات التطبيق والـ APIs
│   ├── services/
│   │   ├── ai_service.py     # محرك الذكاء الاصطناعي للتلخيص وفحص الأدوية
│   │   └── qr_service.py     # توليد وتشفير أكواد الـ QR المؤقتة
│   └── templates/            # واجهات المستخدم (Bootstrap 5 RTL)
│       ├── base.html         # القالب العام والمكتبات
│       ├── index.html        # الصفحة الرئيسية واختيار المرضى الـ 10
│       ├── patient_dashboard.html # بوابة المريض وعرض الـ QR
│       ├── doctor_dashboard.html  # بوابة الطبيب ومسح الرمز
│       ├── clinical_view.html     # الشاشة السريرية والـ AI Hub
│       └── kaggle_data.html       # جدول استعراض داتا Kaggle الأصلية
├── data/
│   ├── cardiology_patients.json          # تفاصيل الـ 10 حالات السريرية
│   └── kaggle_heart_disease_benchmark.csv # داتا Kaggle المعيارية المفتوحة
├── requirements.txt          # مكتبات البايثون المطلوبة
├── run.py                    # تشغيل خادم التطبيق المحلي
└── README.md                 # دليل التوثيق الشامل
```

## 🚀 6. طريقة التشغيل (Quick Start)

1. تثبيت الحزم المطلوبة:
   ```bash
   pip install -r requirements.txt
   ```
2. تشغيل السيرفر:
   ```bash
   python run.py
   ```
3. فتح المتصفح على:
   ```text
   http://127.0.0.1:5000
   ```
